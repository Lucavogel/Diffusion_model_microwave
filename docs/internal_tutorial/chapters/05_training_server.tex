\chapter{Train and Deploy the Policy}
\label{chap:training}

Training is the only stage normally run on the GPU server. The exact Docker,
transfer, and training commands are maintained in \filepath{README_SERVER.md};
use that guide rather than reconstructing an old terminal history.

\section{Keep the Four Execution Contexts Distinct}

\begin{table}[H]
  \centering
  \begin{tabularx}{\textwidth}{@{}p{0.25\textwidth}X@{}}
    \toprule
    \textbf{Context} & \textbf{Typical work} \\
    \midrule
    Local experiment PC & Collect, replay, and validate the Zarr dataset. \\
    GPU server host & Store the transferred project and start or enter Docker. \\
    Docker container & Activate \filepath{robodiff} and run training from \filepath{/workspace}. \\
    Local deployment PC & Load and execute the copied checkpoint in MuJoCo or on the robot. \\
    \bottomrule
  \end{tabularx}
\end{table}

The path \filepath{/workspace} exists only inside the container. Commands that
fail with a missing \filepath{/workspace} on the local PC are being run in the
wrong context.

\section{Minimal Training Sequence}

\begin{enumerate}
  \item Check the final local dataset and stop editing it.
  \item Transfer that dataset, the matching task/training YAML files, and the
  source required by the selected model.
  \item Enter the persistent Docker container and activate \filepath{robodiff}.
  \item Print the dataset path inside Docker and pass it explicitly as
  \filepath{task.dataset_path}.
  \item Launch the matching training configuration inside a \filepath{tmux}
  session and monitor GPU use with \filepath{nvidia-smi}.
  \item Copy several checkpoint candidates back to
  \filepath{data/checkpoints/} on the local PC.
\end{enumerate}

For a MuJoCo dataset recorded by this guide, the matching configurations are
\filepath{train_e_waste} and \filepath{e_waste_image}. After following the
container and configuration-copy steps in \filepath{README_SERVER.md}, launch
this example from inside Docker:

\begin{lstlisting}[language=bash]
cd /workspace
source /opt/conda/etc/profile.d/conda.sh
conda activate robodiff

DATASET_NAME="<simulation_dataset>.zarr"

python /workspace/diffusion_policy/train.py \
  --config-name=train_e_waste \
  task=e_waste_image \
  task.dataset_path="/workspace/data/datasets/$DATASET_NAME" \
  training.resume=False \
  training.device=cuda:0 \
  logging.mode=disabled \
  logging.resume=False
\end{lstlisting}

For another task or model, replace both configuration names together. The task
YAML must describe exactly the recorded keys, image sizes, state
dimensions, action dimensions, and horizons. A checkpoint trained with a real
dataset configuration must not be tested with the simulation interface, or the
reverse.

Select a few checkpoints around the best validation region and test them under
the same conditions. Validation loss is useful for identifying overfitting, but
the final choice must also produce stable closed-loop behavior.

\begin{checkpointbox}[Checkpoint ready]
The checkpoint loads on the local PC, its dataset and resolved configuration
are known, and its observation/action interface matches the runner that will
execute it.
\end{checkpointbox}
